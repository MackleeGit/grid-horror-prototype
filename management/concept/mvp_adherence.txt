Sticking strictly to a Minimum Viable Product (MVP) first is the gold standard in game and engine programming. Build the foundation clean, and layered features drop into place smoothly without breaking your graphics engine.

Because of how modern C++ and OpenGL pipelines are structured, every advanced feature you mentioned maps directly onto the core architecture without requiring a rewrite.

---

**How Future Expansions Fit the Architecture**

* **Second Floor & Staircases:** Upgrade the 2D map array into a 3D array (`grid[floor][row][col]`). Stacking cube meshes along the $Y$-axis creates multi-story buildings, while stairs use inclined bounding box collision routines to adjust `cameraPos.y` smoothly.
* **Breathing & Hiding QTEs:** Handled in C++ via a game state machine (`enum GameState { EXPLORING, HIDING_QTE }`). While hiding, a timer loop tracks keypress timing (e.g., holding `Space` inside a rhythmic window). Failing the QTE sets `isPlayerHidden = false`, alerting the monster.
* **Noise Mechanics:** Add a player noise radius float derived from movement speed ($\text{noiseRadius} = \text{velocity} \times \text{modifier}$). If sprinting, the radius expands; if the monster intersects this radius, it switches from a random patrol state to an active chase state.
* **2D UI Overlay (QTE Prompts & Fuse Count):** Rendered using a second GLSL shader pipeline with an **Orthographic Projection Matrix** ($2\text{D}$ screen space overlay) sitting directly on top of your $3\text{D}$ perspective view.
